# 一篮 · 好食材，好生活，一篮就够

**一篮是一款围绕「买什么、怎么做、剩下什么」设计的日常做饭助手。**

它把几天的用餐计划、采购清单、家中库存、当顿选菜和做饭教程连成一个流程，帮助用户根据真实的生活安排和厨房条件，少一点纠结，把买回来的食材接着用起来。

> 这是可实际操作的移动 Web 原型，不是静态设计稿。页面由真实组件、动态状态和交互逻辑组成；iPhone 外框仅用于展示。

**[立即体验 →](https://yilan-yvonne.netlify.app/preview.html#/login)** · **[手机全屏体验](https://yilan-yvonne.netlify.app/#/login)** · **[当前完整源码](https://github.com/Yvonne93-design/A-basket/tree/feature/iphone17-v0)**

线上体验不要求登录 Netlify，也不依赖开发者电脑开机。进入欢迎页后，可点「先看看」浏览，或点「开始设置」体验首次使用。当前完整实现位于 `feature/iphone17-v0` 分支。

## 为什么做一篮

日常做饭的困难，往往不只是缺一道菜谱：

- 买菜前，不确定接下来几天在家吃几顿、该买多少。
- 买菜后，冰箱里有食材，却不知道怎样组合成一餐。
- 同时做几道菜时，不知道先洗切什么、怎样安排锅具。
- 做完之后，剩余食材和下一次采购又重新变成一次决策。

一篮以「一轮采购与用餐」为单位，把这些分散的决定串起来。目标是减少重复决策和不必要的采购，而不是让用户管理一张复杂的库存表；目前尚未进行真实用户效果量化验证。

## 核心体验：从一篮食材到一餐饭

| 环节 | 用户做什么 | 产品如何响应 |
| --- | --- | --- |
| 设置自己的厨房 | 填写人数、饮食限制和可用厨具 | 后续规划与选菜带入这些条件 |
| 再搭一篮 | 选择日期范围、预计餐次、饮食偏好和想吃的菜 | 结合已有食材生成本轮建议与采购清单 |
| 确认采购 | 调整数量、勾选实际买到的食材，也可一键全选 | 只有确认购买的项目进入库存 |
| 今天做什么 | 浏览候选菜，把想做的放到餐桌上 | 按整餐合计检查用量，提示不能选择的原因 |
| 开始做饭 | 跟随多菜时间轴，查看动作图与具体操作 | 合并可共用的准备工作，依据步骤依赖和锅具安排先后 |
| 完成与记录 | 确认实际用量，保存这一餐 | 扣减对应库存、生成食记，让剩余食材进入下一轮规划 |

**一个关键例子：**冰箱里的番茄和鸡蛋可能分别够做番茄炒蛋或蛋汤，但不一定够同时做两道。一篮会检查整张餐桌的需求，避免每道菜单独看都能做、加在一起却不够的情况。

## 四个主要页面

- **菜篮**：查看本轮安排、采购清单和家中食材，补充食材或再搭一篮。
- **做饭**：根据现有食材和当顿偏好挑菜，组织待做餐桌，进入整餐教程。
- **食记**：回看吃过的、收藏想吃的，浏览「美食广场」和体验发帖。广场目前使用示例内容与本机帖子，不是真实多人社区。
- **我的**：管理个人用餐习惯、饮食限制和厨房条件。

视觉以米白方格纸、橄榄绿和温暖手绘素材为主。手写字体用于主要标题，正文使用清晰的中文无衬线字体，让工具流程保留日常生活的亲近感。

## 建议用 3 分钟这样体验

1. 从「开始设置」填写用餐习惯与厨房信息；也可以点「先看看」进入示例。
2. 在菜篮点「再搭一篮」，选择几天的安排、餐次与想吃的菜，生成建议。
3. 核对采购清单，调整数量，勾选已购买项目并完成入库。
4. 到做饭页选择两道菜，观察餐桌变化和食材是否足够的提示。
5. 进入教程，查看准备步骤、多菜时间轴与动作配图。
6. 完成后核对实际用量，回到菜篮与食记，查看库存扣减和新记录。

每位访客的数据保存在自己的浏览器中。演示库存、食记和广场内容不代表真实采购或真实用户数据。

## AI 在这里负责什么

一篮将模型建议与可核验的业务规则分开：

| 能力 | 当前实现与边界 |
| --- | --- |
| 食材规划 `planBasket` | 已实现服务端模型接入与结果校验；未配置或调用失败时使用本地规则规划 |
| 菜品推荐 `recommendRecipes` | 综合库存、偏好和厨房条件；候选仍须通过程序校验 |
| 做饭策略 `proposeCookingStrategy` | 已有模型接口；教程基础步骤、依赖和厨具排程有本地实现 |
| 数量、库存与采购 | 由程序处理，不依赖模型自由计算；完成一餐重复提交不会重复扣库存 |
| 动作配图 | 本地透明素材按动作匹配，即时加载，不等待远程生成图片 |
| 拍照识图 | 当前公开版本仍为原型／模拟能力，不能当作真实小票或食材识别服务 |

**当前公开 Netlify 版本未配置一篮的模型密钥，使用已有本地规则回退。**因此主流程可以体验，但不能把本次线上演示描述为真实模型调用结果。

## 已实现与尚未实现

**可以实际操作：**用餐与厨房设置、周期规划、采购确认与入库、库存筛选、整餐用量检查、选菜餐桌、做饭教程、实际用量确认、库存扣减、食记和想吃的收藏，以及本机发帖交互。

**尚未成为生产服务：**真实账号登录、跨设备同步、多人社区、真实图片识别。数据使用浏览器 `localStorage` 保存，清除网站数据会清除本机记录。教程时长为估算值，不能替代用户对实际火候与熟度的判断。

## 工程与本地运行

- **前端**：原生 HTML / CSS / JavaScript ES Modules，Hash 路由与移动端自适应布局。
- **状态**：浏览器 `localStorage`；采购和做饭完成由独立业务模块校验。
- **服务端**：Node.js HTTP 服务与同源 AI 网关；Netlify 通过 Function 适配已有网关。
- **素材**：本地插画、动作图、菜品图与中文字体，不依赖运行时生成图片。
- **验证**：Node 内置测试工具。运行应用无需第三方 npm 依赖。

建议 Node.js 22.9 或以上：

```sh
git clone --branch feature/iphone17-v0 --single-branch https://github.com/Yvonne93-design/A-basket.git
cd A-basket
npm ci
npm start
```

打开 `http://localhost:4173/preview.html` 查看带手机外框的版本，或打开 `http://localhost:4173` 查看自适应页面。

```sh
npm run check   # 语法检查
npm test        # 业务与网关测试
npm run build  # 生成云端部署文件
```
