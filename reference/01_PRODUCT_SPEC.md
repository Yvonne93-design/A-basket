# 一篮 - Product Spec

## 1. 产品定义
「一篮」是一款围绕**真实采购周期**运行的 AI 食材规划与做饭协同产品。

用户只需要表达：这轮准备几天、预计做几顿、上一篮剩余、这几天大概想吃什么、是否有几道明确想吃的菜、做饭时更看重什么；系统负责把这些输入转成**可修改的食材方案与购买量**，采购后维护真实库存，做饭时再根据真实库存生成具体菜品与整餐教程。

不是：菜谱 App、冰箱库存 App、固定周菜单、AI 聊天助手、医疗营养工具、生鲜电商。

## 2. 一级页面职责
- **菜篮**：这一轮买什么、买了什么、还剩什么。
- **做饭**：当前真实食材下，这顿具体做什么、如何一起做。
- **食记**：吃过的记录 + 想吃的意愿池。
- **我的**：长期稳定上下文（厨房、默认人数、长期过敏/绝对忌口、账号/会员）。

## 3. 三层上下文
- **长期**（我的）：默认人数、厨房/灶位/厨具、过敏、绝对忌口。
- **周期**（再搭一篮）：天数、预计餐次、上一篮剩余、本轮风格/细分、从“想吃的”选出的锚点菜、做饭习惯。
- **即时**（做饭/换个方向）：这顿人数、想吃类型、时间、少洗锅/少切配、当前圆桌、当前真实库存。
即时条件不写回周期；周期偏好不写回长期。

## 4. 核心用户流
```text
登录/初始设置
→ 菜篮
→ 再搭一篮
→ AI 食材建议
→ 用户调整并确认
→ 采购清单
→ 实际购买 / 顺手买了识别
→ 用户确认后写真实库存
→ 做饭页具体菜卡
→ 点心上圆桌 / × 删除 / 换个方向
→ 开始做饭
→ 整餐协同教程
→ 完成 + 确认实际用量
→ 库存扣减 + 可选写食记
→ 下一轮承接剩余
```

## 5. 再搭一篮（核心）
页面按设计稿纵向滚动，组件顺序：
1. 准备多久：3/5/7天/自定义。
2. 大约在家做几顿：2/3/4/自定义。
3. 上一篮剩余：可选择是否带入本轮计算。
4. 本轮大风格：中式/日式/韩式/西式/东南亚/还没想好；可多选。
5. 细化（可选）：只展开已选大风格对应细类。
6. **特别想吃（可选）**：从“想吃的”打开 Bottom Sheet，多选具体菜；这些是 AI 规划锚点，不等于固定菜单，也不与餐次数量一一对应。
7. 做饭习惯（可选）：20分钟内、少洗锅、少切配、一锅出、适合带饭等。
8. CTA：生成这一篮的食材建议。

### Wanted Picker Bottom Sheet
- 搜索 / 分类 / 多选 / 已选数量 / 确定。
- 选中后回到“再搭一篮”显示可删除小卡。
- “想吃的”页本身不生成采购计划。

## 6. AI 食材方案
AI 读取：周期 + 预计餐次 + 默认人数 + confirmed stock + 风格/细分 + 锚点菜 + 做饭习惯 + 厨房 + 长期限制。

内部流程：
1. 从结构化 Recipe Library 检索真实可行菜品。
2. 优先容纳用户锚点菜。
3. 形成内部参考组合（只用于估算，不展示成固定菜单）。
4. 优先共享食材、承接剩余、减少只用一次的材料。
5. 程序汇总配方需求并计算差额：`purchaseQty = max(0, requiredQty - confirmedStockQty)`。
6. 输出食材建议，可 +/-、删除、锁定，并可查看简短原因。

若锚点菜之间食材高度分散：显示代价与替代方案，让用户决定；不得自动删用户选择。

## 7. 采购与库存
状态必须分开：`suggested → shopping → bought → stock`。
- AI 建议不能直接入库存。
- 采购清单可勾“实际买到”并修改实际数量。
- 小票/食材图像识别只给候选；用户确认后才加入采购草稿或库存。
- 同一食材可以有多个批次 StockLot，不能合并后丢失购入日期。

## 8. 做饭页
默认候选综合：真实库存、本轮风格、锚点菜、近期实际吃过、需优先关注的库存、厨房能力、当顿即时条件。

### 菜品卡
- 必须对应 `recipe_id` / 已验证 `recipe_variant_id`。
- 横滑 = 浏览下一张，不写长期 dislike。
- 点心 = 加入当前餐桌，不扣库存。

### 圆桌
- 圆形/椭圆透视桌面是核心交互。
- 已选菜真实摆上桌；每道有 `×`；空位可继续加。
- 自动汇总整餐食材总需求并检查库存冲突。

### 换个方向 Bottom Sheet
只影响当前一顿：
- 当顿人数；
- 想吃类型（米饭配菜/盖饭拌饭/面条米粉/汤粥/沙拉拌碗/还没想好）；
- 选中类型后的按需细化；
- 风味；
- 整餐时间；
- 少洗锅/少切配/一锅出；
- 食材策略：现有食材优先，可接受少量补买。
更新候选时保留桌上已有菜；冲突时让用户决定。

## 9. 做饭教程
点击“开始做饭”直接进入教程，不再增加独立食材确认页。
- 单菜：图解为主。
- 多菜：AI 重新编排整餐流程：合并洗切、先长耗时步骤、利用等待时间、按灶位/锅具并行或串行、少洗锅时考虑复用、易凉菜靠后。
- 页面纵向长滚动，具象手绘步骤图 + 极短文字，减少做饭时点击。

## 10. 食记 / 想吃的
食记 L1：`吃过的 | 想吃的`；右上“拍照记一道”。
- 拍照/相册 → AI 菜名/标签候选 → 用户修改 → 选择保存到“吃过的”或“想吃的”。
- “想吃的”是意愿库；可标记“下一篮候选”，但不直接生成采购清单。
- 真正批量选取：再搭一篮 → 从想吃的挑。

## 11. 我的 / 我的厨房
“我的”只放长期稳定条件与账户：个人资料、默认人数、我的厨房、过敏/绝对忌口、会员/通知/隐私/帮助/账号。

我的厨房记录：灶位数量、锅具/电器类型、数量、可用状态。支持首次拍照识别、确认、新增、修改数量、停用、删除、重新扫描。

## 12. 产品文案
AI 文案必须：短、直接、先结论后依据。禁止无功能价值的“幸福感满满/AI懂你/再不吃就坏了”等氛围小字。
